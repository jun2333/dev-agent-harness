# 2026-08-19 — v0.5 编排器引擎 + 插件发现机制改造

## 背景

经过数轮实战（taskflow 需求构建 + 看板体验增强两个真实流程），把 harness 从"LLM 自读自执行"推进到**程序驱动的编排器**，并重构插件发现机制为"只读项目知识库"。同时修复实战暴露的一批路径/记账/流程问题。

## 改进项

### 1. 编排器引擎（orchestrator/，新）

- **core.js 状态机**：start / next / validate / advance / approve / status；参数全部来自文件（manifest / checkpoint / stage-result），脚本参数禁止 LLM 生成（全局约束）
- **validate.js**：两层校验（结构层固定协议 + 规则层机械检查）；`sections_ok` 子代理自报不采信，以机械检查为准
- **stage-check.js**：从 gate-check 提取共享校验（checkStage/checkVerifyEvidence），gate-check 与 validate 单一真相源
- **prompt-builder.js**：阶段指令组装（含 executor）
- **adapters/**：bridge（LLM 中转，默认）/ headless（脚本直调 `codebuddy -p`）双形态；executor 可配置（默认 inline，subagent 显式用于重步骤隔离）
- **pre/post_stage 程序化执行**：skill-log / context-snapshot 由编排器每阶段无条件记账；env-check 接入 start
- **任务完成**：自动生成 review-brief.md 审核简报

### 2. 插件发现机制改造（只读项目知识库）

- **workflow-lib.js**：只读 `knowledge/plugins/`（内置插件变模板源，不再通用兜底）；`knowledge/plugins` 缺失 → **抛错给 LLM**（边界检查，提示先初始化）
- **workflow-init.js**：init 复制**整个插件目录**（workflow.yaml + check/ + templates/）；**路径规范化自动修正**（过时 `.md` skill 引用 → `/SKILL.md`，支持主 skill 与 post_stage/pre_task 的 `- skill:`）；checkCommandPool 识别插件自带 check 脚本
- requirements skill 格式修正为 `{name}/SKILL.md` 标准格式
- 通用插件补充 executor 配置（重步骤 subagent、轻量 inline）

### 3. 上下文控制与日志

- **日志全局按日**：`tool-actions/YYYY-MM-DD.log`，每条带 `task_id`（来自 `.active-task.json` 全局任务状态，编排器 start 写 / done 清）；非任务状态 task_id 为 null
- **只记主代理**：子代理读取不做记账（能读什么由 prompt + 交接文档限定），context-snapshot 按 task_id 过滤生成已读清单（脚本查询，不耗 token）

### 4. 强制进编排层

- checkpoint 带 `executor: orchestrator` 标记；orchestrate skill 声明默认强制走编排器
- `start` 校验 manifest 的 `user_confirmed: true`（启动会话三件事经 AskUserQuestion 确认）
- `advance` 对 user_approval 阶段强制检查 `approved_stages`（废弃 `--approved` 绕过，必须先 approve 落盘）
- gate-check Stop 对非编排器任务软提示"建议走编排器"

### 5. 实战问题修复

- **skill 路径大小写**：workflow 引用 `skill.md` → `SKILL.md`（macOS 侥幸可访问，Linux 会挂）
- **bridge prompt 路径解析**：`knowledge/` 开头 → 项目根，否则 `.harness/`
- **context-ledger 双写者冲突**：子代理写 `context-ledger.raw` → 编排器合并生成 md（后续简化为只记主代理，raw 移除）
- **implementing TDD**：先写失败测试 → 实现 → 测试通过
- **human-review-feedback 内嵌**：反馈区块移入 review-report.md 末尾，不再指向模板文件

## 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| executor 默认 | `inline` | 主 agent 直接执行，宿主 hook 全部生效；subagent 显式用于需要隔离的重步骤 |
| 插件来源 | 只读 `knowledge/plugins/` | 减少用户心智负担（单层）；内置插件 = 模板源，`workflow-init init` 复制 + 路径规范化 |
| 日志组织 | 全局按日 + task_id | 按日归档便于清理；脚本按 task_id 过滤不耗 token；显式全局任务状态比推断可靠 |
| 记账范围 | 只记主代理 | 子代理 hook 记录不到（实测），能读什么由 prompt 限定 |
| gate 审批 | approved_stages 落盘 | `--approved` 参数可被桥绕过，审批标记是唯一通过凭证 |
| 失败重做 | config.max_rework（默认 2） | 超限停等人工介入，提示明确 |
