# 2026-07-16 — v0.3 优化计划实施（阶段零 + 阶段一 + 阶段二）

## 背景

基于 [dev-agent-harness 优化计划](../docs/ai-agent/harness-engineering/dev-agent-harness-optimization-plan.md)，实施阶段零到阶段二的改造，解决项目级 skill 手工维护不可持续的问题，并引入轻量 CLI 工具提升可靠性。

## 改进项

### 阶段零：Skill 模板继承机制

**问题**：`knowledge/skills/` 下的 skill 是项目特定的，每个项目都要手工维护通用规范，新项目容易遗漏。

**改动**：
- 创建 `skills/domain-templates/` 目录，包含 5 个框架级标准 skill 模板（designing、task-planning、implementing、testing、reviewing）
- 模板中内置通用规范（Summary for downstream、Anti-Cherry-Pick、Decision Log）
- 改造 `skills/tools/knowledge-init/SKILL.md`，`skills` 子命令基于框架模板生成项目特定 skill
- 更新 `skill-interface.md`，添加"框架标准模板继承机制"说明

**效果**：新项目通过 `knowledge-init skills` 自动继承通用规范，无需手工同步。

### 阶段一：纯文本增强（模板补充）

**问题**：部分模板缺少通用规范区块。

**改动**：
- `templates/design-output.md`：添加 Decision Log 区块
- `templates/review-report-output.md`：添加 Anti-Cherry-Pick Declaration 和问题统计
- `templates/context-ledger.md`：新建上下文追踪模板
- `harness.md`：添加"产出物规范"和"Context Ledger"章节

**效果**：所有产出物格式统一，决策可追溯，上下文读取可追踪。

### 阶段二：轻量 CLI 工具引入

**问题**：验证命令依赖 AI 自觉运行，可能跳过或伪造结果；skill 执行日志需要手动填写。

**改动**：
- `tools/verify.js`：验证命令执行器，强制执行命令并捕获真实 exit code 和日志
- `tools/skill-log.js`：技能日志自动化工具，自动记录执行时间戳和基本信息
- 所有 `skills/domain-templates/*.md`：添加 skill-log 的 start/complete 调用步骤
- `skills/domain-templates/testing.md`：添加 verify.js 调用步骤和 verification_commands 字段

**效果**：验证结果不可伪造，skill 执行自动留痕。

## 设计决策

### verification_commands 的存放位置

**决策**：`verification_commands` 定义在项目 testing skill 中（`knowledge/skills/testing/SKILL.md`），而非 workflow.yaml。

**理由**：
- workflow.yaml 在框架中，项目没有自己的 workflow
- knowledge-init 生成 testing skill 时，根据 scan 产出的技术栈信息生成具体的 verification_commands
- testing skill 执行时读取自己定义的 verification_commands，调用 verify.js

**备选方案**：
-  定义在 workflow.yaml 中 → 项目无法覆盖（没有自己的 workflow）
- ❌ 定义在单独的配置文件中 → 增加复杂度，skill 自包含更简单

### CLI 工具的职责边界

**决策**：CLI 工具（verify.js、skill-log.js）只负责执行和记录，不读取 skill 配置。

**理由**：
- 保持 CLI 工具通用，不耦合 skill 结构
- skill 执行时读取配置，通过参数传给 CLI 工具
- 职责清晰：skill 负责"做什么"，CLI 负责"怎么做"
