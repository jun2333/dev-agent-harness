# 2026-08-18 — v0.4 验证命令项目化（堵住证据链自证漏洞）

## 背景

hook 门禁只校验"verification-result.json 存在且 passed"，但 `verify.js run --commands="..."` 的**命令是 LLM 自己选的**——`node verify.js run --commands="echo hi"` 也能产出 `overall_status: passed` 的证据文件，gate 照样放行。证据链的信任锚点回到了 LLM 的自觉（v0.3 决策"CLI 工具不读 skill 配置"的副作用）。

## 改进项

### 1. verify.js 命令项目化（他证原则）

- 新增项目配置 `knowledge/verify.config.json`（`verify.config.v1`），命令由项目拥有、随项目版本管理，由 knowledge-init 生成
- `verify.js run` 不再接受 `--commands`：向上查找项目根 `knowledge/verify.config.json`，从配置读取命令清单；传 `--commands` 直接拒绝并报错
- 每个命令带超时（默认 300s，可配置）、cwd 固定为项目根、捕获真实 exit code / 日志 / 耗时 / 超时标记
- 报告新增 `config_source` / `config_schema_version` 字段，标注证据来源

### 2. gate-check 证据对账

- testing/reviewing 阶段证据校验升级：报告命令必须与项目配置**对账**——
  - 配置命令必须全量执行（禁止只跑部分）
  - 证据中不允许出现配置外命令（禁止自选命令 = 禁止自证）
- 缺少配置 / 缺 config_source / 报告未覆盖配置命令 → 一律 exit 2 阻塞

### 3. gate-check 按阶段校验必含区块

- 由单一 `## Summary for downstream` 升级为按阶段必含区块（任选其一语义）：
  - designing / task-planning → Summary + Decision Log
  - testing → Summary + 完整性声明（或 Anti-Cherry-Pick Declaration）
  - reviewing → Summary + Anti-Cherry-Pick Declaration
- 阻塞反馈补充"重做该阶段产出工作，而不是只修补报告文件"的指引（修过程而非修症状）

### 4. 配套修正

- `templates/task-plan-output.md` 补上缺失的 `## Decision Log` 区块（harness.md / skill-interface.md 均强制要求）
- `skills/domain-templates/testing.md`：verify 调用去掉 `--commands`，路径修正为 `.harness/workspace/{task-id}/...`（与 gate-check 实际校验路径一致）；`verification_commands` 字段替换为配置说明
- `skills/tools/knowledge-init/SKILL.md`：`skills` 子命令新增生成 `knowledge/verify.config.json` 步骤
- `hooks/check-verify.js`：提醒文案同步
- `skill-interface.md`：新增"验证命令项目化"规范

## 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 配置位置 | `knowledge/verify.config.json`（项目层） | workflow.yaml 在框架层项目无法覆盖；skill 是 markdown 不可机器读取；知识库是项目拥有的版本化层 |
| 是否保留 `--commands` | 删除并拒绝 | 保留即留洞；项目配置是新增命令的唯一合法通道 |
| 对账方向 | 配置⊆证据 且 证据⊆配置 | 全量执行 + 禁止自选，双向闭合 |
| 路径修正 | 模板统一为 `.harness/workspace/{task-id}/` | 与 gate-check 实际校验路径对齐，消除既有不一致 |
