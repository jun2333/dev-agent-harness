# 2026-06-26 — v0.2 借鉴 spec-first 优化可控性与知识沉淀

## 背景

深入研读了 [spec-first](https://github.com/sunrain520/spec-first) v1.12.0 项目的验证系统、知识沉淀系统和 source/runtime 架构，提炼出 5 个轻量化改进落地到 harness。

## 改进项

### 1. 测试报告模板加反 cherry-pick 规则

**问题**：AI 可能只汇报通过的测试用例，隐藏未运行或失败的用例。

**改动**：`templates/test-report-output.md` 增加"完整性声明"区块，要求列出所有声明要跑的用例，未运行的必须标记原因，总体结论在有 not-run 时强制为"未完成"。

**来源**：spec-first 的 honest-closeout 机制和 verification-run-summary 聚合逻辑。

### 2. Lessons 加失效条件和回源路径

**问题**：经验老化只看时间和 use_count，无法判断经验是否因源码变更而过时。

**改动**：
- `skills/reflecting/SKILL.md`：经验草稿和收集阶段增加 `invalidation_condition` 和 `source_refs` 字段
- `skills/knowledge-init/SKILL.md`：知识文件格式和淘汰规则加入回源检查逻辑

**来源**：spec-first 的 compound 系统，每条 learning 必须声明失效条件和回源路径。

### 3. 产出物模板加 Summary 区块

**问题**：下游阶段经常不读上游产出物就开始工作，或者把全文塞进 context 导致 token 浪费。

**改动**：6 个模板（task-input、design-output、task-plan-output、test-report-output、review-report-output、tech-selection-output）头部统一增加 "Summary for downstream" 区块，包含目标、范围、关键结论、已知风险、下游关注文件。

**来源**：spec-first 的 artifact-summary.v1 和 summary-first 交接协议。

### 4. harness.md 加反合理化红旗表

**问题**：AI 常见的偷懒念头（跳步、假装验证通过、顺手改无关代码）只在 prompt 里隐式提及。

**改动**：`harness.md` 增加"反合理化红旗"表，列出常见偷懒念头和对应纠正动作，让 AI 在产生这些念头时能"看见"自己在合理化。

**来源**：spec-first AGENTS.md 中的 anti-rationalization red flags 设计。

### 5. Skill 接口规范加确定性/判断分离

**问题**：skill 的输入和判断混在一起，AI 容易越界（假装跑过验证、臆造事实）。

**改动**：
- `skill-interface.md`：SKILL.md 格式规范增加"确定性输入"和"语义判断"分离要求
- 4 个通用层 skill（reflecting、knowledge-init、project-init、state-checkpoint）各自的执行步骤中标注确定性输入和语义判断的边界

**来源**：spec-first "Scripts prepare, LLM decides" 原则。

## 未采纳的设计

以下 spec-first 设计虽好，但对轻量 harness 来说过重，暂不引入：

- **verification-profile / verification-run-summary JSON schema**：需要 CLI 工具链，当前纯 Markdown 方案够用
- **双宿主支持（Claude Code + Codex）**：harness 面向 QoderCLI，不需要多宿主
- **context-bundle.v1 上下文预算协议**：context-rules/ 已经覆盖，不需要独立 schema
- **dual-host governance / orphan detection**：单仓库不需要
